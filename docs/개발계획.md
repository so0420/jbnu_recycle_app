## 1. 방향

웹(모바일 화면 기준 SPA)으로 먼저 만들고, 마지막 주에 Capacitor로 안드로이드 앱으로 감싼다.

| 원칙 | 내용 |
|---|---|
| 모바일 화면 기준 | 폭 360~430px. PC 크롬 기기 모드로 개발 |
| 카메라·위치는 웹 표준 API | `<input type="file" accept="image/*" capture="environment">`, `navigator.geolocation` → 웹과 앱(WebView) 양쪽에서 동작 |
| 판정·계산은 전부 서버 | AI 호출, 위치 판정, 경험치·공격권. 클라이언트가 보낸 값은 믿지 않는다 |
| HTTPS | 폰 카메라·위치는 HTTPS에서만 동작 → SER9 Max에서 `cloudflared` 터널 |

## 3. 서버 PC: Beelink SER9 Max 운용

### 3-1. 사양과 역할
| 항목 | 값 | 비고 |
|---|---|---|
| CPU | AMD Ryzen 7 H 255, 8코어 16스레드, 최대 4.9GHz | 판매처에 따라 H 260/H 350 모델도 있으니 실물 확인 |
| GPU | Radeon 780M 내장 (12CU), 시스템 RAM 공유 | NPU 없음 → AI는 CPU 또는 내장 GPU로 실행 |
| RAM | 32GB DDR5-5600 (2×16) | |
| 저장 | 1TB NVMe (M.2 슬롯 2개) | |
| 네트워크 | 10GbE + 2.5GbE | |

**이 PC 한 대에서 전부 돌린다**: MariaDB, FastAPI(+빌드된 프론트), Ollama(clef-flash), cloudflared 터널, 사진 저장소.
팀원은 SSH(`server_connection.env`)로 접속한다. **키 파일과 이 env 파일은 git에 올리지 않는다.**

### 3-2. 메모리 배분 (32GB)

| 항목 | 예상 사용량 |
|---|---|
| OS + 기본 서비스 | 3~6GB (리눅스 쪽이 적음) |
| Ollama `clef-flash` 9B **Q4_K_M** + 컨텍스트 8K | 약 7~9GB (모델 파일 약 6GB) |
| MariaDB (`innodb_buffer_pool_size=512M`) | 약 1GB |
| FastAPI (uvicorn 워커 2개) + 이미지 처리 | 약 1GB |
| 여유 | 약 15GB |

- 9B는 이 PC에서 "작은 모델"로 무리 없이 올라간다. **Q8_0**(파일 약 10GB, 16K 컨텍스트에서 약 14GB)도 들어가므로 1주차에 정확도와 속도를 비교해서 고른다.
- 상위 모델 `clef`(27B)는 메모리에는 겨우 들어가도 응답이 너무 느려서 실사용은 어렵다고 보고 제외한다.
- **모델은 1개만 상주**시킨다. 인증 사진 판정도 같은 `clef-flash` 로 한다. 사진 중복 검사는 AI가 아닌 pHash(CPU, 수 ms)로 한다.

### 3-3. Ollama 설정
```bash
OLLAMA_HOST=127.0.0.1:11434     # 외부에 직접 열지 않음. FastAPI만 접근
OLLAMA_KEEP_ALIVE=-1            # 모델을 메모리에 계속 올려 둠 (첫 요청 지연 제거)
OLLAMA_NUM_PARALLEL=1           # 동시 처리 1개 (메모리·속도 안정)
OLLAMA_MAX_LOADED_MODELS=1
OLLAMA_CONTEXT_LENGTH=8192      # System One 요청은 짧음. 이미지 토큰 + 질문이면 충분
```
- **GPU 가속 확인**: 780M을 Ollama가 잡는지(Vulkan/ROCm) `ollama ps` 의 PROCESSOR 열로 확인한다. 안 잡혀도 CPU로 동작하지만 느리다. GPU를 쓸 때 메모리가 모자라면 BIOS의 iGPU 공유 메모리(UMA)를 8GB → 16GB로 올려 본다.
- FastAPI 쪽에서도 **동시 호출 1개 + 대기열**(`asyncio.Semaphore(1)`, 대기 20초 넘으면 타임아웃)을 둔다. 타임아웃이 나거나 대기열이 3개를 넘으면 OpenAI 2차로 바로 넘기거나 클라우드 모델을 쓴다.

### 3-4. 1주차 성능 측정 (AI 담당, 결과를 이 문서에 표로 기록)
`scripts/bench_system_one.py`: 라벨 달린 사진 30장 × {Q4_K_M, Q8_0} × {긴 변 512, 768, 1024px} 조합을 돌린다.

| 기록할 값 | 판정 기준 |
|---|---|
| 응답 시간 p50 / p95 (모델이 이미 올라간 상태) | **p95 ≤ 6초** 면 로컬 사용 |
| 대분류 top1 정확도 | 조합 중 정확도가 가장 높고 기준 시간을 만족하는 것 선택 |
| 메모리 사용량 (`ollama ps`, 작업 관리자/`free -h`) | 여유 8GB 이상 유지 |
| CPU/GPU 중 어디서 돌았는지 | |

- p95가 6초를 넘으면: 이미지 크기 축소 → 그래도 안 되면 **`clef-flash:cloud`** (설정값 `SYSTEM_ONE_URL` 만 바꿈).
- AI용 이미지는 저장용(1280px)과 따로 **긴 변 768px**에서 시작한다. 이미지가 클수록 토큰이 늘어 느려진다.

### 3-5. 운영
| 항목 | 방법 |
|---|---|
| 실행 | `docker compose` (MariaDB + FastAPI) + Ollama·cloudflared는 OS 서비스로 등록 → 재부팅 시 자동 시작 |
| HTTPS 주소 | 팀 도메인이 있으면 **named tunnel**(고정 주소, 카카오맵 도메인 등록이 쉬움). 없으면 quick tunnel(`*.trycloudflare.com`, 재시작할 때마다 주소가 바뀌어 카카오 콘솔에 매번 다시 등록해야 함) |
| 팀원 개발 | 각자 PC에서 FastAPI·프론트를 돌리고, AI는 `ssh -L 11434:localhost:11434 서버` 로 SER9의 Ollama를 빌려 씀 → **팀원 PC에 모델 설치 불필요**. DB는 각자 docker MariaDB |
| 백업 | 매일 새벽 `mysqldump` + `uploads/` 를 두 번째 디스크나 외장 디스크로 복사 (7일 보관) |
| 모니터링 | `/health` (DB·Ollama 연결 확인), 로그 파일 회전. 시연 전날 재부팅 테스트 |
| 전원·발열 | 시연 장소에 서버를 가져가지 않는다. 집/연구실에 켜 두고 터널로 접속. 시연용 노트북에 예비 녹화 영상 준비 |

## 4. 시스템 구조

```
[폰 브라우저 / 앱(WebView)]
        │ HTTPS
        ▼
[cloudflared 터널] ──▶ [SER9 Max]
                         ├─ FastAPI (uvicorn)
                         │    ├─ /api/v1/*         API
                         │    ├─ /                 빌드된 React (정적 파일)
                         │    ├─ services/classifier ──▶ Ollama clef-flash (localhost:11434)
                         │    │                     └─▶ OpenAI API (애매할 때만, 인터넷)
                         │    ├─ services/game.py     경험치·공격권·청결도
                         │    └─ APScheduler          자정 처리, 시즌 종료, 백업
                         ├─ MariaDB (docker)
                         └─ uploads/ (사진)
```

### 배출 인증 처리 순서 (`POST /api/v1/verify`)
1. 프론트: 촬영 → 긴 변 1280px JPEG로 축소 → 위치(`lat, lng, accuracy`) + `idempotency_key` 와 함께 업로드
2. 서버: 같은 `idempotency_key` 가 이미 처리됐으면 이전 결과를 반환
3. 위치: `accuracy` > 100m면 거절 → 반경 안의 가장 가까운 `places` 를 찾고 거리 ≤ max(50, min(accuracy, 100))m 인지 확인
4. 같은 수거장 오늘 인증 여부, 하루 상한 확인
5. EXIF 촬영 시각 검사(있을 때만), pHash 중복 검사
6. 사진 판정: System One `noul` → 0.7 이상이면 통과, 0.4~0.7이면 OpenAI, 0.4 미만이면 실패
7. 통과 시 `game.on_verification()` 를 한 트랜잭션으로 실행(XP, 청결도, 공격권, 주간 목표) → 결과 반환
8. 의심 신호(이동 속도 이상, 2차 판정 경계값)가 있으면 `flagged=1` 로 표시 → 관리자 검토

## 5. AI 분류 파이프라인

v1의 3장 구조를 그대로 유지하고, 구체적인 값만 정한다.

| 항목 | 값 |
|---|---|
| 1차 | `clef-flash` (Ollama `/v1/systemone`), 질문 `choice`(대분류) + `noul`(오염 여부) |
| 2단계 질문 | 대분류(10~12개) → 필요한 경우 세부 품목(26개 이하). **세부 질문은 대분류 확률 0.6 이상일 때만** 해서 호출 횟수를 줄인다 |
| 애매함 기준 | top1 < 0.60 또는 (top1 − top2) < 0.15 → 2차 (1주차 측정 후 조정) |
| 2차 | OpenAI 이미지 입력 모델, JSON 응답, 1차 상위 3개 후보를 함께 전달 |
| 2차도 낮음 | 사용자에게 후보 3개 중 선택하게 함 → 선택 결과를 `classify_logs.final_label` 에 저장 (나중에 정답 데이터로 활용) |
| 배출 방법 문장 | AI가 쓰지 않는다. `item_guides` 표에서 꺼낸다 |
| 타임아웃 | 1차 15초, 2차 20초. 둘 다 실패하면 "텍스트로 검색하기"로 안내 |
| 기록 | 모든 요청의 1차·2차 결과, 소요 시간, 최종 라벨을 `classify_logs` 에 저장 → 발표 지표 "1차에서 끝난 비율 = OpenAI 비용 절감률" |

**선택지(criteria) 관리**: `app/services/classifier/labels.yaml` 한 파일에 영어 설명과 `item_guides.label` 키를 같이 둔다. 틀리는 품목이 나오면 이 파일만 고친다.

- FastAPI가 만들어 주는 `/docs`(OpenAPI)를 프론트 팀과 계약서처럼 쓴다. 프론트 타입은 `openapi-typescript` 로 자동 생성한다.

## 7. DB 스키마

```
-- 기본
places          id, kind(재활용|의류|판매소|무인회수기|...), name, address, detail,
                region_id, lat DECIMAL(10,7), lng DECIMAL(10,7), hours, items,
                is_active, source(분리의정석|전주시|제보), source_id      INDEX(lat, lng), INDEX(region_id)
regions         id, code(행정동코드), name, gu, zone_id, population, dump_weekdays(예: "1,3,5")
zones           id, name                      -- 시연용 권역
users           id, login_id, password_hash, nickname, role(user|admin),
                region_id, region_confirmed_at, region_changed_at,
                xp, level, tickets                                   -- 캐시
item_guides     id, label, name_ko, category, method, caution, image_hint
verifications   id, user_id, place_id, photo_path, phash, lat, lng, accuracy, distance_m,
                result(success|fail), fail_code, judged_by(system_one|openai), score,
                flagged, idempotency_key UNIQUE, created_at
classify_logs   id, user_id, photo_path, phash, s1_json, s2_json, final_label,
                judged_by(system_one|openai|user), latency_ms, created_at

-- 게임 (상세는 게임시스템.md 8-1)
seasons, region_states, region_events, region_adjacency,
xp_events, ticket_events, user_daily, user_weekly, daily_job_log, season_results
```
- Alembic 마이그레이션은 **서버·게임 담당 한 명만** 만든다. 동시에 만들면 리비전이 갈라진다.
- 개발용 `scripts/seed_dev.py`: 테스트 사용자 30명, 가짜 인증 기록, 시즌 1개를 만든다. 화면 개발할 때 빈 화면이 나오지 않게 한다.
