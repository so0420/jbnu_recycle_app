## jeonju_places.csv

열: `source,source_id,kind,name,address,detail,lat,lng,hours,items,dong_code,dong_name,gu,is_active,note`

- `source`: `bunri`(분리의정석만), `bunri+jeonju`(전주시 생활지리정보와 매칭됨). `source_id` = 통합본 `ID`.
- `kind` 개수: bag_shop 1,983 / clothes_bin 1,008 / recycle_point 491 / other 83 / reverse_vending 43 / battery_bin 12
  - battery_bin = 분리의정석 '폐가전 수거함(중소형 수거함)' 12곳. 배출품목이 모두 "건전지,소형전자제품"이라 여기에 넣었다. 건전지·형광등만 받는 전용 수거함 데이터는 없다.
  - other = 폐휴대폰 배출처 79, 이모빌리티 배출처 2, 폐의약품 수거함 2 (원래 구분은 `note` 에 적음).
  - reverse_vending 43곳 중 2곳은 '빈용기 반환수집소'다.
- `name`: 판매소는 가게 이름(원본 상세주소 칸), 나머지는 원본 장소명. `detail`: 상세주소 + 전주시 위치설명.
- `dong_code/dong_name/gu`: 좌표가 들어가는 **행정동** (point-in-polygon). 원본의 법정동과 다르다.
- `is_active=0` (15곳, 모두 분리배출장소): 전주시 특이사항이 '미사용', '마을자체수거함(미사용)', '사용안함'인 곳. '관리안됨', '파손' 같은 다른 특이사항은 `note` 에만 적었다.
- 좌표: 전주시와 매칭된 422곳은 전주시 원본 좌표를 쓴다(분리의정석 좌표와 중앙값 약 19m 차이). 다만 전주시 좌표가 전주시가 적은 행정동 밖에 있고 분리의정석 좌표는 그 안에 있는 2곳(ID 175519, 265632)은 분리의정석 좌표를 썼다.

### 알려진 문제
- **제외 41행**: 통합본의 전주시 행 3,661개 중 좌표가 없는 46행에서 전주시 원본 좌표로 채운 5행(분리배출장소)을 뺀 41행(판매소 32, 의류수거함 9). 주소만 있고 지오코딩하지 않았다.
- 같은 종류·같은 좌표 중복 의심 3쌍(무인회수기 1쌍, 분리배출장소 2쌍): `note` 에 '중복의심' 표시만 하고 지우지 않았다. 판매소는 한 건물에 가게가 여럿이라 좌표가 겹쳐도 표시하지 않았다(359행).
- 전주시가 적은 행정동과 좌표로 찾은 행정동이 다른 분리배출장소 6곳: `note` 에 `전주시표기행정동=` 으로 남겼다.
- 주소의 구와 좌표로 찾은 구가 다른 곳 1곳(의류수거함 265833, 덕진구 공북로 10-6 → 완산구 중앙동, 구 경계 근처).
- 행정동 경계 밖으로 떨어지는 장소는 없다.
- 원본 데이터 시점이 2024년 말이라 그 뒤 생기거나 없어진 수거함은 반영되지 않았다.

## jeonju_dongs.geojson
- properties: `code`(10자리 행정동 코드, `adm_cd2`), `name`, `gu`. WGS84(CRS84).
- 원본이 이미 일반화된 경계라 허용오차 0으로 두고(겹치는 꼭짓점만 정리) 좌표만 소수 6자리(약 0.1m)로 반올림했다(`--simplify` 로 조정 가능).
- 전북특별자치도 출범(2024) 뒤 코드라 `52111`(완산구), `52113`(덕진구)으로 시작한다. 스크립트는 옛 코드 `45111/45113` 도 인식한다.

## jeonju_dongs.csv
열: `code,name,gu,population,population_date,center_lat,center_lng,neighbors`
- `population`: 2026년 10월 말 주민등록 총인구수(거주자 + 거주불명자 + 재외국민, 외국인 제외). 35개 동 모두 있고, 합계 617,648명은 전주시 전체와 같다. 행안부 코드와 admdongkor 코드 35개가 모두 일치한다.
- `center_lat/lng`: 폴리곤 무게중심. 무게중심이 폴리곤 밖이면 내부 대표점을 쓴다.
- `neighbors`: 경계를 공유하는 행정동 코드(`;` 구분). 약 10m 버퍼를 준 경계와 겹치는 면적이 있으면 인접으로 본다.

## 전국 파일 (kr_*)

### kr_dongs.csv
열: `code,name,sido,sido_code,sigungu,sigungu_code,population,population_date,center_lat,center_lng`
- admdongkor 2026-10-01 판 행정동 3,559개 전부. `sigungu_code` = 코드 앞 5자리 (경계 파일의 `sgg` 와 3,559개 모두 같음).
- 구가 있는 시는 구가 시군구 단위이고, 이름은 "전주시 완산구"처럼 쓴다 (13개 시, 39개 구. 2026년 새로 생긴 화성시 만세·효행·병점·동탄구 포함).
- 세종특별자치시는 시군구 하나(`36110`, 이름 "세종시")로 들어 있다. 군위군은 대구광역시(`27720`) 아래에 있다.
- 광주광역시와 전라남도는 경계 파일과 행안부 통계 모두 `전남광주통합특별시`(시도 코드 12) 하나로 나온다.
- `population`: 2026년 10월 말 주민등록 총인구. 3,559개 동 모두 값이 있다. 합계 51,075,077명으로 행안부 전국 합계(51,075,282명)보다 205명 적다(아래 사천시 신수출장소).
  - 행안부 목록에는 경계가 따로 없는 **출장소**(예: 순천시 해룡면신대출장소 32,741명)가 별도 행으로 있다. 이름이 상위 읍면동으로 시작하거나 코드 앞 7자리가 같으면 그 읍면동 인구에 더했다(59건, 예: 보령시 원산출장소 → 오천면).
  - 평택시 고덕1동·고덕2동(행안부)은 경계 파일에 아직 고덕동 하나라 합쳐서 고덕동에 넣었다.
  - 상위 동을 확실히 알 수 없는 **경상남도 사천시 신수출장소(205명)는 넣지 않았다**. 그래서 사천시 합계만 행안부보다 205명 적다.
  - 인구 0 이고 경계도 없는 10곳(철원군 근동면 등 비거주 지역, 인구 0 출장소)은 버렸다.
- 확인: `kr_sigungu.csv` 의 인구는 사천시를 빼고 행안부 시군구 합계와 모두 같다.

### kr_sigungu.csv
열: `sigungu_code,sido,sigungu,population,center_lat,center_lng,dong_count`
- 256개. `population` 은 소속 행정동 인구의 합. 중심점은 소속 행정동을 합친 폴리곤의 무게중심(밖이면 내부 대표점).
- 인접 행정동(neighbors)은 전국 파일에는 없다.

### kr_places.csv.gz
- 열과 규칙은 `jeonju_places.csv` 와 같다. 단 `gu` 에는 시군구 이름("전주시 완산구", "종로구", "세종시")을 넣었다. 전주 행은 `gu` 만 빼고 `jeonju_places.csv` 와 값이 같다.
- gzip(mtime 0)이라 같은 입력이면 같은 파일이 나온다. 읽을 때: `pd.read_csv("kr_places.csv.gz", dtype=str)`.
- `kind` 개수: bag_shop 96,361 / other 34,002 / battery_bin 31,747 / clothes_bin 25,879 / recycle_point 22,561 / reverse_vending 1,707
  - battery_bin = 전지 수거함·형광등 수거함 21,330 + 배출품목에 건전지가 있는 폐가전 수거함 10,417
  - other = 기타(폐휴대폰·아이스팩·영농폐기물 등) 12,159, 음식물 RFID 10,425, 폐의약품 7,179, 물품교환처 2,026, 건전지 없는 폐가전 수거함 1,365, 폐식용유 848
  - 구분이 빈 행은 장소명으로 정했다(의류수거함 → clothes_bin).
- `is_active=0` 은 전주시 자료가 있는 15곳뿐이다. 다른 지역은 사용 여부 정보가 없어 모두 1이다.

### 알려진 문제 (전국)
- **제외 2,583행**: 통합본 214,840행 중 좌표가 없는 행(판매소 1,986, 의류수거함 258, 분리배출장소 141, 기타 50, 음식물 RFID 48, 전지 34, 구분없음 33, 형광등 25, 폐가전 8). 좌표가 한국 범위(위도 33~38.7, 경도 124.5~132) 밖인 행은 없었다.
- 행정동 경계 밖 좌표 139개: 137개는 2km 안의 가장 가까운 행정동을 넣고 `note` 에 `행정동경계밖(최근접 Nm)` 을 적었다(중앙값 31m, 최대 407m, 대부분 해안 매립지. 예: 거제 고현항). 2km 넘게 떨어진 2개(군산 새만금로 2478, 옥도면 야미도리 159, 새만금 매립지)는 행정동을 비워 두었다.
- 원본 시도와 좌표로 찾은 시도가 다른 행 19개(예: 경기 광명시 하안로 → 서울 금천구 14개). 시도 경계 근처 지오코딩 오차로 보이며, 좌표 결과를 그대로 두었다.
- 원본 시군구와 좌표로 찾은 시군구가 다른 행 1,344개. 대부분은 원본이 화성시 구 신설(2026) 전이라 "화성시"로만 적힌 경우(1,049개)이고, 나머지는 경계 근처 오차다.
- 같은 종류·같은 좌표 중복 의심 11,422행: `note` 에 표시만 했다(판매소 제외).
- `.gitattributes` 에 `*.gz binary` 가 없다. gzip 에는 NUL 바이트가 있어 git 이 바이너리로 처리하겠지만, 명시하려면 루트 `.gitattributes` 에 추가하면 된다.
